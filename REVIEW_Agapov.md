## C-01. Повторная подготовка при нулевом запасе

**Источник:** SPEC.md, Т-04; tests/test_acceptance.py, ПТ-03, ПТ-09.  
**Важность:** major.

При совпадении уровней `equalize()` должен завершаться без расхода воды. В ПТ-03 повторная подготовка проверяется при запасе 1. В ПТ-09 запас достигает нуля, но повторной подготовки нет. Поэтому тесты пропускают ошибочный запрет любого `equalize()` при `reserve == 0`.

В ПТ-09 после подготовки перехода на участок 3 состояние равно `(2, 5, 0, 2)`. Повторный `equalize(1)` должен вернуть `None` и сохранить этот снимок. Последующий `cross(1)` должен дать `(3, 5, 0, 3)`.

**Исправление:** добавить повторный вызов в ПТ-09, проверить возврат и полный снимок. Дополнить описание сценария в TEST_CASES.md.

## C-02. Обратное направление через именованный аргумент

**Источник:** SPEC.md, раздел 4, Т-08; tests/test_acceptance.py, ПТ-02.  
**Важность:** minor.

Вызов по имени аргумента проверяется только для `direction=1`. Обратное направление везде передаётся позиционно. Ошибка обработки `direction=-1` останется незамеченной.

На новом объекте выполнить:

```python
capsule.equalize(1)
capsule.cross(1)
capsule.equalize(direction=-1)
capsule.cross(direction=-1)
```

После обратной подготовки ожидается `(1, 1, 2, 1)`, после перехода — `(0, 1, 2, 2)`. Обе команды должны вернуть `None`.

**Исправление:** дополнить ПТ-02 обратным переходом с именованным аргументом. Проверить возвраты и снимки, обновить TEST_CASES.md.

## C-03. Сохранение изменённого состояния при неверном направлении

**Источник:** SPEC.md, Т-08, Т-09; tests/test_acceptance.py, ПТ-11.  
**Важность:** major.

ПТ-11 проверяет неверные аргументы только на новом объекте. Если команда перед `ValueError` ошибочно сбрасывает состояние к начальному, тест этого не обнаружит.

Для каждой команды, `equalize` и `cross`, отдельно создать объект и выполнить `equalize(1)` → `cross(1)`. Состояние станет `(1, 4, 1, 1)`. Вызвать проверяемую команду с аргументом `0`.

Ожидается `ValueError` без изменения значений и точных типов полей. Сброс к `(0, 1, 4, 0)` недопустим.

**Исправление:** повторить проверки недопустимых аргументов из ПТ-11 после перехода на участок 1. Использовать `assert_rejected` для обеих команд, обновить TEST_CASES.md.
