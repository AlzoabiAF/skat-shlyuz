# План тестирования

1. На ревью проверить, что уровни, расход и восстановление воды однозначно выводятся из ТЗ, а подготовка каждого сценария достижима через публичный API.
2. До реализации проверить синтаксис и обнаружение 14 приёмочных тестов. Запуск сценариев требует модуля `skate_lock.py`.
3. После реализации выполнить все сценарии на Python 3.10 или новее. Команда — `python -m unittest discover -s tests -t . -v`.
4. При отказе сравнить первое расхождение с ожидаемым снимком. Зафиксировать ID сценария, версию Python, коммит, результат и фактическое состояние. Приёмка требует 14 успешных тестов.

## Протокол будущей приёмки

На входе нужны согласованная версия ТЗ, обработанные замечания ревьюеров и реализация в известном коммите. Результат приёмки фиксируется после фактического прогона.

- Версия и коммит согласованного ТЗ — ожидается ревью.
- Коммит реализации, дата, ОС и версия Python — заполнить при запуске.
- Команда и ссылка на лог — заполнить при запуске.
- Ожидается 14 успешных тестов, без ошибок и пропусков.
- Фактический результат и решение автора — заполнить после прогона.

При изменении согласованного требования указать в журнале причину, связанные тесты и результат повторного ревью.
